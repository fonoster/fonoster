## Why

There are four ways to run Fonoster from a checkout and none of them is the rebuild: the legacy
`npm run start:services` (`compose.dev.yaml` with InfluxDB, Mailhog, Adminer, a fake GitHub and
autoheal), the `start:*` scripts that read the old `config/*.yaml` paths, `.env.example.dev`, and
the everything-in-containers `ops/rebuild/stack`. The dev container only holds Node and asks the
contributor to start the dependencies on the host. A new contributor cannot tell which path works,
and none of them runs the components we develop (apiserver, gateway, Autopilot, media node,
dashboard) from source with reload next to the dependencies they need.

## What Changes

- **The dev container is the only way to develop Fonoster.** It is a Compose-based dev container
  (`.devcontainer/compose.yaml`): a `workspace` service (Node 22, Go 1.25, protoc) plus the
  dependencies (Postgres, NATS, Routr, RTPEngine, MinIO, Envoy) taken from the self-host bundle's
  own service definitions (`extends` of `ops/bundle/compose.yaml`), so dev and self-host cannot
  drift. Opening the dev container starts the dependencies; there is no "start db" command.
- **Our components run from source with reload inside the workspace**: `npm run dev:apiserver`,
  `dev:gateway`, `dev:autopilot`, `dev:medianode` (Go, rebuilt on change), `dev:dashboard` (Vite),
  `dev:fakes` (fake TTS/STT/LLM), and `npm run dev` for all of them with prefixed logs.
- **One dev config, generated by `fonoster-config init`** into the git-ignored `.dev/` folder
  (`.env` with the generated secrets, `config/` with the service files and keys), with a small
  committed dev layer (`.devcontainer/config/`: fake providers, the workspace's addresses).
  `npm run dev:config` re-renders it and keeps every secret.
- **Tests work inside the dev container** against dedicated dependencies: a NATS for the
  conformance suite (`CONFORMANCE_NATS_URL`) and a test database
  (`PERSISTENCE_TEST_DATABASE_URL`), both defaulted in the dev container's environment.
- **Removed**: `compose.dev.yaml`, `.env.example.dev`, `npm run start:services` /
  `stop:services`, the legacy `start:*` service scripts, `db:migrate`, `generate:keypair`,
  `.scripts/check-preconditions.sh`, `.scripts/gen-keypair.sh` and the old CONTRIBUTING setup
  sections. `ops/rebuild/stack` stays as the CI/smoke harness, not a contributor path.
- **BREAKING** (contributors only): the old commands are gone; `npm test` no longer needs a root
  `.env`.

## Impact

- New spec: `developer-environment`.
- Files: `.devcontainer/*`, `.scripts/dev.mjs`, root `package.json` scripts, `.gitignore`,
  `CONTRIBUTING.md`, CI workflows that copied `.env.example.dev`, `mods/apiserver/src/bin/entrypoint.ts`
  (seed from source), `mods/dashboard/vite.config.ts` (`/config.js` from the environment in dev),
  `ops/bundle/config/envoy.yaml` (WebSocket upgrade on the dashboard route, for Vite HMR).
