# Build log: revamp-developer-experience

Decisions taken while building, for the owner to review. Each can be reversed.

## 2026-10-16

### DX-B1. Compose-based dev container (coordinator's choice)

- `.devcontainer/compose.yaml` with `dockerComposeFile` / `service: workspace` / `runServices`.
  The dependencies are the bundle's own service definitions (`extends` of
  `ops/bundle/compose.yaml`), so images, health checks, fixed addresses and published ports match
  self-host. Our own services are not containers in dev. Owner can override.

### DX-B2. The dev config is written on the host, before the containers (initializeCommand)

- Compose interpolates the bundle's `${POSTGRES_PASSWORD:?run fonoster-config init}` when it reads
  the file, and RTPEngine needs the host's LAN address, which only the host sees. So
  `.devcontainer/initialize.sh` (POSIX sh + Docker only) runs the real `fonoster-config init`
  from source in a throwaway `node:22-alpine` (installs only `yaml`, `ajv`, `tsx` there, versions
  from the lockfile) the first time the dev container opens. post-create runs `npm run dev:config`
  again with the built CLI (keeps every secret). This differs from "generated by post-create": too
  late for Compose.
- `.dev/.env.example` is the bundle's `.env.example` with the dev defaults (project
  `fonoster-dev`, subnet `10.216.31`, `PUBLIC_URL=http://localhost:${HTTP_PORT}` for the browser
  microphone) plus `CONFIG_DIR` (absolute host path, so the bundle's relative mounts resolve to
  `.dev/config`). `FONOSTER_DEV_<NAME>` on the host overrides any value on first write (ports,
  `HOST_IP`).
- `.devcontainer/.env` is a link to `.dev/.env` (made by the script, git-ignored): Compose's
  project folder is `.devcontainer`.

### DX-B3. `extends`, not `include`, for the bundle's services

- `include` brings every bundle service, including ours and their dependencies (Envoy depends on
  the apiserver). `extends` takes just nats, postgres, routr, rtpengine, minio and envoy, with
  their images, health checks, fixed addresses and ports; Envoy's `depends_on` is `!reset`. The
  network block (5 lines) and volume names are repeated.

### DX-B4. The workspace takes the media node's address and our services' names

- Workspace at `<prefix>.42` (the bundle's media-node address, inside Routr's LOCALNETS) with
  aliases `apiserver gateway autopilot medianode dashboard fakes`. The bundle's Envoy routes,
  `apps.autopilotUrl`, `routr.apiEndpoint` and the media node's config work unchanged. Only the
  gateway's RTP address is overridden (`.devcontainer/config/gateway.yaml`).
- `.dev/config` is mounted read-only at `/config`, `/etc/fonoster` and `/opt/fonoster/keys`: the
  services find their files, keys and catalog at the bundle's paths without flags.

### DX-B5. Fake providers by default in dev

- `.devcontainer/config/{gateway,autopilot}.yaml` (overlays, the rebuild stack's mechanism): fake
  TTS/STT/LLM on localhost:7001-7003 (`npm run dev:fakes`, part of `npm run dev`). Real vendor
  keys: per workspace in the dashboard, or a platform key in `.dev/overlay/<service>.yaml` +
  `.dev/.env`, then `npm run dev:config`.

### DX-B6. One runner, no new dependency

- `.scripts/dev.mjs`: ~200 lines, Node only. `concurrently` is not in the lockfile. Loads
  `.dev/.env` with the CLI's own `readEnvFile`/`expandEnv` into each child (not the workspace's
  environment: tests stay clean and a change needs no container rebuild). TypeScript services:
  `tsx watch`. Media node: `go build` + restart on `.go`/`go.mod` changes via `fs.watch`
  (recursive), failed builds keep the running node; restarts send SIGTERM then SIGKILL after 3 s
  (the node drains calls on SIGTERM). No `air`/`reflex`.
- The apiserver runs its own entrypoint with `--migrate-only` (migrations + seed, as in the
  image) on `.dev/migrations/{core,identity}` (links to `mods/apiserver`, `mods/identity`), then
  `tsx watch src/index.ts`. The entrypoint now runs the seed as `seed.ts` with `process.execArgv`
  when it runs from source (small change in `mods/apiserver/src/bin/entrypoint.ts`).

### DX-B7. Dashboard through Envoy; HMR over the bundle's route

- Vite serves `/config.js` from `DASHBOARD_API_URL` (a 15-line plugin in `vite.config.ts`); the
  runner sets it to `PUBLIC_URL`. The bundle's Envoy dashboard route gained
  `upgrade_configs: websocket` (Vite HMR; nginx ignores it). Root `config/envoy.yaml` is kept equal
  (bundle test).

### DX-B8. Tests get their own NATS and database; no Docker in the workspace

- `nats-test` (plain JetStream, no users) for `CONFORMANCE_NATS_URL`: the dev NATS has per-service
  users, and test gateways must never claim dev calls. Postgres creates `fonoster_test` on first
  start (`.devcontainer/postgres-test.sql`), `PERSISTENCE_TEST_DATABASE_URL` points at it. Both
  set in the workspace's `environment`.
- No Docker CLI in the workspace: the default suites start no containers (the opt-in NATS ACL and
  Routr live tests need Docker and say so).

### DX-B9. Removed

- `compose.dev.yaml` (InfluxDB, Mailhog, Adminer, fake-github, autoheal, legacy Routr/Envoy),
  `.env.example.dev`, `.devcontainer/devcontainer-lock.json` (no features any more), root scripts
  `start:services`, `stop:services`, `start:apiserver`, `start:autopilot`, `start:dashboard`,
  `start:authz`, `start:mcp`, `start:audiosocket`, `db:migrate` (used the removed
  `--preview-feature` flag), `db:seed`, `generate:keypair`, `pretest`, root `nodemonConfig`,
  `start:dev` in apiserver and Autopilot, `.scripts/check-preconditions.sh`,
  `.scripts/gen-keypair.sh` (`.keys/` was unused: the tests use the committed `config/keys`).
- Kept: `.scripts/fake-github.mjs` (run it in the workspace for GitHub sign-in work), package-level
  `start:dev` of amd/authz/mcp/streams (library examples, not platform dev paths), `start:docs`,
  `start:storybook`, the SDK demos, root `config/*.example.*` (the config tests read them).
- CI: no more `cp .env.example.dev .env` (unit tests, conformance, release). `publish-apiserver`
  lost its SDK integration steps, which started the legacy apiserver from `compose.dev.yaml`;
  the SDK integration suite needs a new home on the rebuild stack (coordinator).

### DX-B10. `ops/rebuild/stack` stays the smoke/CI harness

- Unchanged; `docs/try-the-new-platform.md`, `compose.yaml` and `docs/operators/rebuild.md` say it
  is not a development path. Suggest renaming it later (e.g. `ops/smoke/stack`) once CI is moved.
