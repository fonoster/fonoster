# Build log: add-talk-in-browser

Decisions taken while building, for the owner to review. Each can be reversed.

## 2026-10-15

### TB-B1. Read Routr 2.15.1 instead of trusting the legacy flow

- Extracted `@routr/connect` and `@routr/rtprelay` from `fonoster/routr-one:2.15.1`. A connect
  token makes the caller an anonymous agent and the callee the Peer whose `aor` is the token's
  `aorLink` (AGENT_TO_PEER, normal location lookup). The relay already maps WebRTC to `RTP/AVP`
  through RTPEngine. So no Routr change is needed: only config (ws transport, verifier key).
- The token's `domain` (`internal`) doesn't exist in Routr; for AGENT_TO_PEER it isn't used.

### TB-B2. Envoy keeps header case for Routr's WebSocket handshake

- Routr's JAIN-SIP WebSocket server matches `Host` and `Sec-WebSocket-Protocol` case-sensitively.
  Envoy lowercases header names on HTTP/1.1 upstreams, so Routr answered without
  `Sec-WebSocket-Protocol: sip`, which Chrome refuses (proved with `nc` against the container).
- Fix: the `preserve_case` header formatter on the HTTP connection manager and the
  `routr-ws-cluster`, so the browser's own casing reaches Routr. Other routes are unaffected
  (HTTP/2 and gRPC are lowercase by definition; HTTP/1 servers are case-insensitive).
- So the one-port design holds: dashboard, API and SIP signaling all on `HTTP_PORT` (`/sip`).
  No dedicated WebSocket port is published.

### TB-B3. The gateway checks the token, not only Routr (D4)

- Routr forwards the browser's `X-App-Ref` as sent, and the media node trusts it from Routr. The
  gateway now verifies `X-Connect-Token` itself (Node `crypto`, RS256 only, `exp`/`nbf`,
  `allowedMethods` has INVITE) and requires `accessKeyId` = the app's workspace; else SIP 403 and
  a record with `call.failed` reason `test_call_denied`. Without `testCalls.publicKeyFile` a call
  with a token is refused (fail closed). No new dependency.
- No proto change: the token stays per workspace (Empty request), which is enough isolation.
- Not closed here (pre-existing): a registered softphone agent can INVITE the media-node Peer
  with any `X-App-Ref`.

### TB-B4. Signaling URL default and config

- `fonoster.example.yaml` writes `signalingServer: ws://${HOST_IP}:${HTTP_PORT}/sip`. Unset, the
  API server derives it from `appUrl` (`http→ws`, `https→wss`, `/sip`), replacing the legacy
  `wss://<domain>:5062`.
- Test tokens target `routr.mediaNodePeer.aor` (was the Asterisk-era `sip:voice@default`).
- Compose mounts `keys/public.pem` (already generated by init and the stack) into Routr as
  `CONNECT_VERIFIER_PUBLIC_KEY_PATH`; the gateway reads the same file from its keys mount.

### TB-B5. Secure context

- On the bundle without TLS, `PUBLIC_URL` is `http://<HOST_IP>:8449`, not a secure context, so
  browsers hide the microphone. The drawer checks `window.isSecureContext` and says to open the
  dashboard on localhost (or call a number) instead of showing a Call button. Plain `ws://` is
  allowed from an `http://` page, so localhost works with no TLS.

### TB-B6. Dashboard call flow

- Restored the pre-328f43097 sip.js hook and changed it: the microphone is requested first (its
  own error message), then the token, then `connect()` (its own "can't reach the call server"
  message), then the INVITE with `X-App-Ref` and `X-Connect-Token` only (the old
  `X-Access-Key-Id` header is not needed). Mute uses `SimpleUser.mute/unmute`.
- States: idle, connecting, ringing (180/183), connected (timer), ended, failed. Closing the
  drawer hangs up. The numbers list stays below the call card; the "In-browser calls are not
  available yet" note is gone.

### TB-B7. The dashboard's CSP allows `ws:`

- nginx's `connect-src` allowed only `wss:` besides the API origin, so the browser blocked
  `ws://<host>:8449/sip` and sip.js's `connect()` never settled. It now allows `ws: wss:`
  (`mods/dashboard/nginx/40-fonoster-config.sh`), and the hook gives up on `connect()` after 10 s
  with "Couldn't reach the call server".

### TB-B8. RTPEngine ignored the bundle's port range and public address (pre-existing)

- `fonoster/rtpengine:0.3.17` reads `RTPENGINE_PORT_MIN`, `RTPENGINE_PORT_MAX` and
  `RTPENGINE_PUBLIC_IP`; the bundle passed `PORT_MIN`/`PORT_MAX`/`PUBLIC_IP`. RTPEngine used its
  own 23000-32768 (not published) and advertised its container address, so nothing outside the
  Docker network could get media (browsers, and softphones too: ST-B10 never got this far).
  Fixed the names in `ops/bundle/compose.yaml`. The caller-bot call (`stack call`) still passes.

### TB-B9. RTPEngine runs with `--dtls-passive`

- Routr's relay offers the browser leg with RTPEngine in the default active DTLS role, so
  RTPEngine sent a ClientHello before the SDP answer. Chrome cached it, then discarded it when the
  answer (`setup:passive`) made it the client, and both sides waited: ICE connected, DTLS stuck in
  `connecting`, no audio (Chrome WebRTC logs and a packet capture next to RTPEngine).
- `command: ["rtpengine", "--dtls-passive"]` (the image's entrypoint passes extra arguments) makes
  RTPEngine wait for the browser's handshake. Phone calls have no DTLS and are unaffected.

### TB-B10. Live check (dev stack `rb-talk-browser-stack`, ports 17500-17569)

- Headless Chromium (Playwright, fake mic) signed in to the dashboard, opened the Demo agent's
  Talk drawer and clicked Call: 180, 200, "Connected", timer, Mute/Unmute, Hang up, "Call ended".
- WebRTC stats after 8 s: DTLS connected (client), SRTP AES-256-GCM, ~400 RTP packets each way.
  A capture on the media node showed RTP from RTPEngine for the browser leg and from the gateway.
- The sealed call record: `session.start` for the agent, the Autopilot greeting, two turns
  (fake STT/LLM), `end_reason caller_hangup`. Agent-side hangup (gateway `hangup`) sent a BYE to
  the browser over the WebSocket; the drawer showed "Call ended".
- A forged token got 403 from Routr; a validly signed token for another workspace got 403 from
  the gateway (`denied (workspace)`).
- Not tried: a real (non-headless) Chrome with a real mic and speakers, Firefox/Safari, and a
  browser on another machine (needs HTTPS: TB-B5).
