---
title: "Link a Twilio number"
description: "Link a number from your Twilio account from the dashboard or the CLI, and send its calls to an agent, an app or a SIP agent."
---

Link a number you own in Twilio, and its calls reach the agent, app or SIP agent you choose.
Fonoster sets up a SIP trunk in Twilio and in your workspace, and moves the number onto it. You can
also place outbound calls from it.

## Before you begin

You need:

- A Twilio account with a voice-capable phone number in it. Note the number in E.164 format, such
  as `+18095550123`.
- Your Twilio **Account SID**, which starts with `AC`, and one way to sign in to Twilio:
  - **A Standard API key** (recommended): its SID, which starts with `SK`, and its secret. Create
    one in the Twilio console under **API keys & tokens**.
  - **Your Auth Token**. It gives full access to your Twilio account, so prefer an API key.

  Twilio's Restricted keys can't link a number: no Restricted key permission covers the trunk's IP
  access control list, credential list or phone numbers. Use a Standard key.
- An agent, an app or a SIP agent to send calls to. See
  [Build an Autopilot agent](/autopilot/build-an-agent) or
  [Build a stream with the Voice SDK](/streams/voice-sdk).
- For the CLI: [Node.js](https://nodejs.org/) 22 or later.

## Link the number

<Tabs>
  <Tab title="Dashboard">
    <Steps>
      <Step title="Open the link drawer">
        Go to **Numbers**, click **Link number**, then **Twilio number**.
      </Step>
      <Step title="Choose the number and its route">
        Enter the **Number** and choose where to send its calls.
      </Step>
      <Step title="Enter your Twilio credentials">
        Enter your **Twilio Account SID**. Under **Credentials**, choose **API key** or **Auth
        Token** and fill it in.
      </Step>
      <Step title="Link it">
        Click **Link number**. The number shows in the list on **Twilio Trunk**.
      </Step>
    </Steps>

    Twilio now sends the number's calls to Fonoster.

    If the number is already in your workspace, linking moves it to Twilio Trunk and the route you
    choose. A new number is named after itself; rename it under **Numbers**.

    On your own install, Twilio sends calls to your install's public SIP address. Set it up first:
    [Connect carriers and phones](/self-hosting/carriers-and-phones).
  </Tab>
  <Tab title="CLI">
    <Steps>
      <Step title="Install the CLI and log in">
        In the dashboard, go to **API keys** and create a key. Then install the `fonoster` CLI and log
        in to your workspace with the key ID and secret:

        ```bash
        npm install -g @fonoster/ctl
        fonoster workspaces:login
        ```

      </Step>

      <Step title="Run the link command">
        Start the command with the number to link:

        ```bash
        fonoster sipnet:numbers:linkTwilio +18095550123
        ```

        It asks only for what your flags leave out:

        | Prompt | What to enter | Flag |
        | --- | --- | --- |
        | Application | The Autopilot agent or stream that answers the number. Pick **None** to choose later. To send calls to a SIP agent, pass `--agent` instead. | `--app <ref>` or `--agent <aor>` |
        | Twilio Account SID | Your Account SID, which starts with `AC`. | `--account-sid` |
        | How do you sign in to Twilio? | **API key** (recommended) or **Auth Token**. | `--api-key-sid <SK…>` or `--auth-token` |
        | API key SID | Your Standard API key's SID, which starts with `SK`. | `--api-key-sid` |
        | API key secret, or Twilio Auth Token | The secret, typed without echo. | The `TWILIO_API_KEY_SECRET` or `TWILIO_AUTH_TOKEN` variable |

        The number is named after itself in Fonoster. To name it, pass `--name "Support desk"`.

        Fonoster uses your Twilio credentials once, to set up the link, and doesn't store them.

        Confirm the link. Twilio then stops using the number's current voice settings and sends its
        calls to Fonoster. The command prints the number and its trunk when everything is set up:

        ```text
        Linked +18095550123 (number 7d1c3b2a-5e4f-4a6b-8c9d-0e1f2a3b4c5d) on Twilio Trunk (a91e0f44-2b3c-4d5e-8f6a-7b8c9d0e1f2a).
        ```

      </Step>

      <Step title="Check the number">
        List your numbers. The linked number is there, on a trunk named **Twilio Trunk**, pointing at
        the application you picked:

        ```bash
        fonoster sipnet:numbers:list
        ```

      </Step>
    </Steps>
  </Tab>
</Tabs>

Call the number from any phone. Your agent, app or SIP agent answers.

<Check>Your Twilio number rings in Fonoster.</Check>

### Link from a script

Without a terminal, the command never prompts: pass every value as a flag and the secret in an
environment variable. This links a number to an application with a Standard API key:

```bash
export TWILIO_API_KEY_SECRET=...
fonoster sipnet:numbers:linkTwilio +18095550123 \
  --account-sid AC0123456789abcdef0123456789abcdef \
  --api-key-sid SK0123456789abcdef0123456789abcdef \
  --app 4a2f8c1e-0b7d-4a51-9e3c-2f6d7a1b9c00 \
  --yes
```

To sign in with the Auth Token instead, set `TWILIO_AUTH_TOKEN` and pass `--auth-token` in place of
`--api-key-sid`. A missing value stops the command with exit code 1 and names the flag or variable,
such as `Missing --account-sid.` If the number is already in your workspace, the command stops
unless you pass `--yes`, which replaces the number's trunk and route.

## What linking sets up

Linking changes both your Twilio account and your Fonoster workspace. It names everything after
your workspace's access key ID in lowercase, shown here as `wo7d2kq9x4m1c8b3n6p0r5t2v9y4z7a1e3`.

**In Twilio:**

- An Elastic SIP trunk named `Trunk-<access key ID>`, with the termination domain
  `<access key ID>.pstn.twilio.com`. Fonoster sends your outbound calls there.
- An IP access control list named `ACL-<access key ID>` on that trunk, holding Fonoster's
  signaling address. Twilio only accepts outbound calls from addresses on this list.
- A SIP credential list named `CL-<access key ID>` on that trunk, holding the username and password
  Fonoster signs outbound calls with.
- An origination URL `sip:<access key ID>.pstn.fonoster.com` on the trunk. Twilio sends calls to
  your number there.
- Your number moves onto the trunk. Twilio then sends its calls over SIP, not to the number's voice
  webhook.

**In Fonoster:**

- A trunk named **Twilio Trunk**, with the inbound URI `<access key ID>.pstn.fonoster.com` and an
  outbound URI pointing at the Twilio termination domain.
- A credential named `Twilio <access key ID>` on that trunk, matching the one in the Twilio
  credential list.
- The number, on that trunk, pointing at the application you picked.

To link more Twilio numbers, link each one. Fonoster reuses the trunks on both sides and adds the
number.

Numbers linked before this release get the credential when you link them again.

## Change where calls go

The linked number is a normal number in your workspace. To send its calls somewhere else, go to
**Numbers**, open it, and pick a new destination under **When this number is called, send it to**.
See [Numbers and routing](/telephony/numbers).

## On your own install

On a self-hosted Fonoster, the server you're signed in to sets the address Twilio sends calls to
and the addresses Twilio accepts calls from, so the command needs no extra flags. Set your
install's public SIP address first: see [Carriers and phones](/self-hosting/carriers-and-phones).

## Troubleshooting

- **`<number> isn't in Twilio account AC…1234`.** Check the number's E.164 format and the Account
  SID.
- **`Twilio didn't accept these credentials`.** Check the SID and the key or Auth Token.
- **`This Twilio key can't …`.** Use a Standard API key or your Auth Token.
- **`Twilio is unavailable; try again`.** Try again in a few minutes.
- **The number rings but nothing answers.** Check that the number points at an application under
  **Numbers**.
- **Outbound calls fail.** Twilio rejects calls from addresses outside the trunk's access control
  list. On your own install, check your public SIP address in
  [Carriers and phones](/self-hosting/carriers-and-phones).
