The install ships its own Postgres. To use one you manage instead, point every service at it
in its file in `config/`, turn the bundled database off, and start. Do this on a new install:
the bundled database's data isn't moved.

## Before you begin

- Fonoster downloaded and unpacked, but not started yet, see
  [Install with Docker Compose](/self-hosting/install-compose).
- A Postgres you can reach from this machine, over TLS. Every URL below ends in
  `?sslmode=require`; keep it, or the password and your call data travel in clear.
  Certificate verification (`sslmode=verify-full`) isn't covered here.
- Docker Compose v2, as the install page says.

## Create the databases

Create three empty databases. The API server creates the tables in `fonoster` and `fnidentity`
on every start, and the one-shot `routr-migrations` service does the same in `routr` before Routr
starts:

```sql
CREATE DATABASE routr;
CREATE DATABASE fonoster;
CREATE DATABASE fnidentity;
```

## Point every service at it

The Fonoster services take their database URL from their file in `config/`, and Routr from
`.env`, with the same credentials in all four. Replace the bundled URL in each. In `config/fonoster.yaml`, set the API server's `database`
and Identity's `identity.database`:

```yaml config/fonoster.yaml
database: { url: "postgresql://fonoster:9f2c7e1b4a8d3c6e5b0a1f7d2e9c4b8a@db.example.com:5432/fonoster?sslmode=require" }
identity:
  database: { url: "postgresql://fonoster:9f2c7e1b4a8d3c6e5b0a1f7d2e9c4b8a@db.example.com:5432/fnidentity?sslmode=require" }
```

AppBridge and Autopilot share the API server's database. Set `database.url` in
`config/appbridge.yaml` and in `config/autopilot.yaml`:

```yaml config/appbridge.yaml
database:
  url: "postgresql://fonoster:9f2c7e1b4a8d3c6e5b0a1f7d2e9c4b8a@db.example.com:5432/fonoster?sslmode=require"
```

Routr's goes in `.env`, as `ROUTR_DATABASE_URL`. Both `routr-migrations` and `routr` read it:

```bash .env
ROUTR_DATABASE_URL=postgresql://fonoster:9f2c7e1b4a8d3c6e5b0a1f7d2e9c4b8a@db.example.com:5432/routr?sslmode=require
```

These files now hold the database password. Back them up with `.env`, and carry them over when you
[upgrade](/self-hosting/upgrade).

## Turn the bundled Postgres off

The `compose.external-db.yaml` overlay that ships with the install keeps the bundled `postgres`
from starting. Turn it on in `.env` (add `:compose.http.yaml` after it if you serve plain HTTP):

```bash .env
COMPOSE_FILE=compose.yaml:compose.external-db.yaml
```

This is what it does:

```yaml compose.external-db.yaml
services:
  postgres:
    profiles: [bundled-db]
  routr-migrations:
    depends_on: !override {}
  routr:
    depends_on: !override
      routr-migrations: { condition: service_completed_successfully }
      nats: { condition: service_healthy }
  apiserver:
    depends_on: !override
      nats: { condition: service_healthy }
      routr: { condition: service_healthy }
```

## Start

Start, and wait for every service to be healthy. This is what proves the database is reachable:

```bash
docker compose up -d --wait
```

If `routr-migrations` can't reach Routr's database, it exits with an error and Routr doesn't
start; if `routr` can't, it never turns healthy. Either way the command exits with an error. Fix
`ROUTR_DATABASE_URL` in `.env` and start again. A file with a bad key stops its service at
start, and `docker compose logs <service>` names the key.

See what's running:

```bash
docker compose ps
```

`postgres` isn't listed, `routr-migrations` has exited, and `routr` shows `healthy`.

<Check>Every service runs against your database.</Check>

<Note>
  On an external Postgres, the registry tool on
  [Add providers to the catalog](/self-hosting/provider-catalog) needs your database URL in
  `FONOSTER_REGISTRY_DATABASE_URL` instead of the bundled one.
</Note>
