Fonoster calls speech and language vendors for you. Every provider, model and voice has a
**catalog ID** of the form `<provider>/<name>`, and your applications and agents name them by that
ID. This page lists the base catalog that a new install ships with, Deepgram and OpenAI, and
explains how a deprecation shows up.

The catalog your workspace sees can differ: it lists only providers the platform or your workspace
has a key for, and the operator of a self-hosted install can add or remove entries, for example to
add ElevenLabs, Groq or ai-coustics (see [Provider catalog](/self-hosting/provider-catalog)). To
see yours, run:

```bash
fonoster providers:catalog
```

## Where catalog IDs go

| Field | Kind | Example |
| --- | --- | --- |
| `speech.voice` (application) | Voice | `deepgram/aura-2-thalia-en` |
| `speech.sttModel` (application) | Speech-to-text model | `deepgram/nova-3` |
| `speech.ttsModel` (application) | Text-to-speech model | `deepgram/aura-2` |
| `languageModel.model` (agent) | Language model | `openai/gpt-5.4-mini` |

When you save an application, Fonoster checks its voice and speech models against the catalog. A
model that isn't in the catalog is refused, and so is a retired model or voice, with its
replacement in the message. See [Autopilot configuration](/reference/autopilot-config) for every
field.

A voice can also be one that isn't in the catalog, such as a voice from the vendor's own library.
Write it as `<provider>/<vendor's voice ID>` and set `speech.ttsModel` to a text-to-speech model of
the same provider. Fonoster uses the ID as you typed it and doesn't check it:

- A wrong ID fails when the agent speaks, with the vendor's error, and the caller hears nothing.
- A voice that is private to your vendor account works only with
  [your own vendor key](/workspace/provider-keys).
- Without `speech.ttsModel`, or with a model of another provider, the save is refused.

## Voices

These voices run on `deepgram/aura-2`. A voice's language is the one it was made for; the language
the agent listens for is set on the transcriber, with `speech.language`.

| Catalog ID | Language | Gender |
| --- | --- | --- |
| `deepgram/aura-2-thalia-en` | `en-US` | Female |
| `deepgram/aura-2-andromeda-en` | `en-US` | Female |
| `deepgram/aura-2-apollo-en` | `en-US` | Male |
| `deepgram/aura-2-selena-es` | `es-419` | Female |
| `deepgram/aura-2-aquila-es` | `es-419` | Male |

`deepgram/aura-2-thalia-en` is the default voice of a new application.

In the catalog (`fonoster providers:catalog`, or `listCatalog` in the SDK), a voice has its
`language`, its `gender` and, when the vendor gives it, its `accent`, such as `Mexican` or
`British`.

## Language models

We test each language model for speed and tool calling before listing it. Every model below has
streaming and tool calling, and runs at the lowest reasoning level it allows.

Every install has these models:

| Catalog ID | State | Features |
| --- | --- | --- |
| `openai/gpt-5.4-mini` | Active | Streaming, tool calling, JSON mode, reasoning |
| `openai/gpt-4o-mini` | Retired | Replaced by `openai/gpt-5.4-mini` |
| `openai/gpt-4.1-mini` | Retired | Replaced by `openai/gpt-5.4-mini` |

OpenAI shuts down `gpt-4o-mini` and `gpt-4.1-mini` on 2027-01-14; agents that still name them run
on `openai/gpt-5.4-mini`. On a self-hosted install, the operator can also add models served by
Ollama.

## Deprecation and retirement

Each catalog entry is in one of three states:

| State | What it means for you |
| --- | --- |
| `active` | Use it. |
| `deprecated` | It still works. It has a replacement and a retirement date. Move to the replacement before that date. |
| `retired` | It's gone from the catalog. Saved settings that named it were moved to the replacement. |

### When an entry is deprecated

Nothing changes for your calls until the retirement date. You find out in these places:

- **Webhook**: a [`provider.deprecated`](/reference/webhook-events#provider-deprecated) event, sent
  once to each workspace whose saved applications or agents name the entry. It carries `id`,
  `replacement` and `retireOn`.
- **CLI**: `fonoster providers:catalog` shows the state as `deprecated → <replacement>`.
- **Dashboard**: a warning for each deprecated entry your applications name or used lately, with
  the retirement date, the replacement and the applications that use it.
- **Call record**: a call that used the entry notes `provider.deprecated_used`.

To move, change the ID in each application and agent that names it, then make a test call. A
replacement can sound or behave a little differently. See
[Use your own vendor keys](/workspace/provider-keys#when-a-model-is-deprecated).

### When an entry is retired

On the retirement date, Fonoster moves saved applications and agents to the replacement. Settings
the replacement doesn't accept are dropped. A setting that can't move, such as a voice that exists
only on the old model, keeps the old ID, and calls use the replacement for it.

After that:

- The entry no longer appears in the catalog.
- Saving an application with the retired ID is refused, with the replacement in the message.
- A call that still names it runs on the replacement, and its call record notes
  `provider.retired_used`.

If a vendor is down, Fonoster doesn't switch your calls to another vendor on its own. A
[stream](/streams/voice-sdk) gets a `provider_unavailable` error and decides what to do.

## Bring your own keys

By default, calls use the platform's account with each vendor. Set your own key for a provider, and
your workspace's calls use your account instead. A provider the platform has no key for appears in
your catalog once you set one. See [Use your own vendor keys](/workspace/provider-keys).
